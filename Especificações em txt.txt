1. Objetivo
O trabalho tem como objetivo desenvolver uma solução computacional para um
problema real de planejamento, otimização, alocação ou escalonamento,
utilizando técnicas de Inteligência Artificial estudadas na disciplina.
Os estudantes deverão demonstrar capacidade de:
• compreender um problema do mundo real;
• transformar o problema em um modelo computacional;
• identificar variáveis, restrições, estados, vizinhanças e funções de
avaliação;
• implementar algoritmos de Inteligência Artificial;
• comparar diferentes estratégias;
• avaliar quantitativamente os resultados;
• desenvolver um software organizado e executável;
• explicar as decisões adotadas;
• demonstrar experimentalmente as vantagens e limitações da abordagem
implementada.

2. Requisitos comuns a todos os trabalhos
Independentemente do tema, o sistema deverá possuir:
1. leitura ou geração de uma instância do problema;
2. representação computacional adequada;
3. implementação dos algoritmos de Inteligência Artificial;
4. apresentação da solução encontrada;
5. cálculo de métricas de desempenho;
6. possibilidade de executar diferentes instâncias;
7. pelo menos três tamanhos de problema;
8. comparação entre estratégias;
9. tratamento de entradas inválidas;
10.código organizado em módulos ou classes;
11.documentação mínima do código;
12.README explicando como executar o sistema.
Não é necessário desenvolver uma interface gráfica sofisticada.
O sistema poderá funcionar por:
• terminal;
• interface web simples;
• interface desktop;
desde que a solução e os resultados possam ser claramente visualizados durante
a demonstração.

3. Uso de dados
Os problemas representam situações reais.
As equipes deverão utilizar de preferência dados de bases públicas como o
Kaggle; os dados devem anonimizados. Se justificado adequadamente, podem ser
criados dados fictícios ou gerados dados aleatoriamente.
Os dados utilizados deverão estar disponíveis juntamente com o projeto para
permitir a reprodução dos experimentos.

PARTE II – Solução abordada: PROBLEMAS DE SATISFAÇÃO DE RESTRIÇÕES – PSR
7. Requisitos específicos para PSR
As equipes dos temas 7 a 12 deverão representar formalmente o problema como:
PSR = Variáveis + Domínios + Restrições
Deverão implementar obrigatoriamente duas versões.
Versão 1 – Backtracking simples
Implementação do algoritmo de busca com retrocesso sem heurísticas avançadas.
Versão 2 – Backtracking aprimorado
Deverá utilizar obrigatoriamente:
• MRV – Minimum Remaining Values
• Forward Checking
Além disso, deverá utilizar pelo menos uma das seguintes estratégias:
• Degree Heuristic;
• Least Constraining Value – LCV;
• propagação adicional de restrições.

8. Comparação obrigatória – PSR
A equipe deverá comparar:

Backtracking simples × Backtracking aprimorado
Deverão ser medidos:
• tempo de execução;
• número de atribuições realizadas;
• número de retrocessos – backtracks;
• quantidade de estados ou nós explorados.
O objetivo será mostrar se as heurísticas conseguem reduzir o espaço de busca.

9. INSTÂNCIAS DE TESTE
Todos os trabalhos deverão possuir três níveis.
Instância pequena
Deve permitir acompanhar visualmente o funcionamento do algoritmo.
Instância média
Deverá representar uma situação razoavelmente próxima de uma aplicação real.
Instância grande
Deverá pressionar o algoritmo e permitir observar diferenças de desempenho.
Não será necessário que a maior instância seja resolvida instantaneamente.
Caso algum algoritmo apresente dificuldade significativa, esse comportamento
deverá ser analisado pela equipe.

10. EXPERIMENTOS
Os experimentos constituem parte importante do trabalho.
Não será suficiente afirmar:
“O algoritmo encontrou uma solução.”
Os estudantes deverão investigar como e por que o algoritmo encontrou
determinada solução.

Para PSR
Deverá existir uma comparação semelhante a:
Instância Método Tempo Atribuições Backtracks
Pequena Backtracking
Pequena Backtracking + heurísticas
Média Backtracking
Média Backtracking + heurísticas
Grande ...

11. ANÁLISE DOS RESULTADOS
A equipe deverá responder, no mínimo:
1. O Backtracking conseguiu resolver todas as instâncias?
2. Quantos retrocessos foram necessários?
3. MRV reduziu o espaço de busca?
4. Forward Checking produziu melhoria?
5. Qual foi a diferença entre as versões?
6. Como o aumento do número de restrições afetou o problema?

15. DEMONSTRAÇÃO OBRIGATÓRIA
A demonstração deverá utilizar uma instância que não tenha solução previamente
inserida no programa.
Durante a demonstração, a equipe deverá mostrar:
1. dados de entrada;
2. execução;
3. solução encontrada;
4. valor ou qualidade da solução;
5. métricas do algoritmo.
O professor poderá solicitar a modificação de um parâmetro simples.
Exemplos:
• acrescentar um cliente;

• alterar uma indisponibilidade;
• modificar a capacidade;
• trocar o número de equipes;
• alterar um prazo;
• modificar a quantidade de servidores.
O programa deverá recalcular a solução.

TEMA QUE DEVERÁ SER UTILIZADO: 9 Agendamento de consultas/atendimentos PSR
TEMA 9 – AGENDAMENTO DE CONSULTAS OU ATENDIMENTOS
Problema
Uma clínica ou organização precisa distribuir clientes entre profissionais e
horários.
O problema também pode representar:

• atendimento psicológico;
• consultoria;
• atendimento jurídico;
• assistência técnica;
• atendimento acadêmico.
Dados
Profissionais
• especialidade;
• horários disponíveis.
Clientes
• serviço necessário;
• horários disponíveis;
• duração do atendimento.
Salas
• horários disponíveis;
• tipo de sala, quando necessário.
Variáveis
Cada atendimento solicitado.
Domínio
Possíveis combinações:
profissional + horário + sala
Restrições obrigatórias
1. profissional deve possuir especialidade necessária;
2. profissional não pode atender duas pessoas simultaneamente;
3. cliente não pode possuir dois atendimentos simultaneamente;
4. sala não pode ser usada simultaneamente;
5. disponibilidade deve ser respeitada.
Instâncias mínimas
• pequena: 10 atendimentos;
• média: 30 atendimentos;
• grande: pelo menos 60 atendimentos.
Demonstração
Exibir agenda por:
• profissional;

• horário;
• cliente.
Deverá ser possível verificar visualmente a ausência de conflitos.
